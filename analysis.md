# Анализ и моделирование данных предметной области

## 1. Описание предметной области

Предметная область: сервис бронирования авиабилетов.

Сервис бронирования авиабилетов занимается продажей и оформлением авиабилетов на рейсы авиакомпаний, а также регистрацией пассажиров на рейсы.

Основные процессы:

- ведение информации о рейсах;
- поиск рейса по заданным параметрам;
- регистрация пассажиров;
- бронирование и оформление билетов;
- хранение информации о пассажирах;
- учет оформленных бронирований и билетов;
- оформление билетов по результатам бронирования.

Пользователи системы:

- пассажиры (клиенты сервиса);
- сотрудники сервиса бронирования.

Основные задачи информационной системы:

- хранение информации о пассажирах;
- хранение информации о рейсах и авиакомпаниях;
- хранение информации о самолетах, выполняющих рейсы;
- поиск рейсов по направлению и дате;
- учет бронирований пассажиров;
- учет оформленных билетов;
- хранение информации о регистрации пассажиров на рейс;
- просмотр истории бронирований и билетов пассажира.

## 2. Объекты данных
В предметной области выделены следующие основные объекты данных.

### Пассажир
Клиент сервиса, который выполняет бронирование и оформление авиабилетов.

Необходимо хранить:

- идентификатор пассажира;
- имя;
- номер телефона;
- адрес электронной почты;
- номер паспорта.

### Авиакомпания
Компания-перевозчик, которой принадлежат рейсы и самолеты.

Необходимо хранить:

- идентификатор авиакомпании;
- название;
- код авиакомпании (IATA);
- страну регистрации.

### Самолет
Воздушное судно, выполняющее рейс.

Необходимо хранить:

- идентификатор самолета;
- идентификатор авиакомпании;
- модель самолета;
- бортовой номер;
- количество пассажирских мест.

### Рейс
Информация о конкретном авиарейсе, выполняемом по расписанию.

Необходимо хранить:

- идентификатор рейса;
- идентификатор самолета;
- номер рейса;
- город вылета;
- город прилета;
- дату и время вылета;
- дату и время прилета;
- базовую стоимость билета.   

### Бронирование
Информация о бронировании пассажиром места на рейс.

Необходимо хранить:

- идентификатор бронирования;
- идентификатор пассажира;
- идентификатор рейса;
- дату бронирования;
- статус бронирования;
- общую стоимость.

### Билет
Документ, подтверждающий право пассажира на перелет по конкретному рейсу.

Необходимо хранить:

- идентификатор билета;
- идентификатор бронирования;
- номер билета;
- номер места;
- класс обслуживания;
- дату оформления.

### Регистрация
Информация о регистрации пассажира на рейс.

Необходимо хранить:

- идентификатор регистрации;
- идентификатор билета;
- дату и время регистрации;
- номер посадочного места;
- статус регистрации.

## 5. Связи между объектами
Между объектами предметной области были определены следующие связи.

### Пассажир - Бронирование
Тип связи: один ко многим (1:N).

Один пассажир может иметь несколько бронирований. Каждое бронирование относится к одному пассажиру.

### Рейс - Бронирование
Тип связи: один ко многим (1:N).

На один рейс может быть оформлено несколько бронирований. Каждое бронирование относится к одному рейсу.

### Бронирование - Билет
Тип связи: один ко многим (1:N).

В рамках одного бронирования может быть оформлено несколько билетов (например, при групповой поездке). Каждый билет относится к одному бронированию.

### Билет - Регистрация
Тип связи: один к одному (1:1).

По одному билету оформляется одна регистрация на рейс. Каждая регистрация относится к одному конкретному билету.

### Авиакомпания - Самолет
Тип связи: один ко многим (1:N).

Одна авиакомпания может владеть несколькими самолетами. Каждый самолет принадлежит одной авиакомпании.

### Самолет - Рейс
Тип связи: один ко многим (1:N).

Один самолет может выполнять несколько рейсов. Каждый рейс выполняется одним самолетом.

### Рейс - Пассажир (через бронирование)
Тип связи: многие ко многим (M:N).

Один пассажир может бронировать места на разные рейсы. Один рейс может быть забронирован многими пассажирами. Связь реализуется через промежуточную таблицу «Бронирование», которая содержит идентификатор пассажира и идентификатор рейса.

## 6. Концептуальная модель данных
На схеме отражены следующие связи:

- Пассажир 1:N Бронирование;
- Рейс 1:N Бронирование;
- Бронирование 1:N Билет;
- Билет 1:1 Регистрация;
- Авиакомпания 1:N Самолет;
- Самолет 1:N Рейс;
- Пассажир M:N Рейс (через Бронирование).

Связь многие ко многим между пассажиром и рейсом реализована с помощью промежуточной таблицы «Бронирование».

## 7. Оценка качества исходных данных
После построения концептуальной модели была выполнена оценка полноты и качества данных.

### Достаточно ли объектов выделено?
Да. Выделенные объекты описывают основные данные, необходимые для ведения информации о рейсах, поиска рейсов, регистрации пассажиров, бронирования и оформления билетов.

### Отсутствуют ли важные сущности?
Для рассматриваемой модели основных сущностей достаточно. При дальнейшем развитии системы могут быть добавлены города и аэропорты (справочники), платежи, тарифы, багаж, скидки и другие объекты.

### Все ли необходимые атрибуты определены?
Для построения концептуальной модели определены основные атрибуты каждого объекта. При реализации реальной информационной системы набор атрибутов может быть расширен (например, тип салона, условия возврата, данные о багаже).

### Имеются ли дублирующиеся данные?
Явного дублирования данных в модели нет. Информация о пассажирах, авиакомпаниях, самолетах, рейсах, бронированиях, билетах и регистрациях хранится в отдельных объектах и связывается между собой. Города вылета и прилета хранятся непосредственно в рейсе; при развитии системы их целесообразно вынести в отдельный справочник.

### Достаточно ли информации для дальнейшего проектирования информационной системы?
Да. Выделены основные объекты, их атрибуты и связи. Полученная модель может использоваться как основа для дальнейшего проектирования базы данных.
